## Core

| Term | Meaning | Learn more |
| --- | --- | --- |
| **BaaSForge** | Backend architecture platform: typed units + managed runtimes + multi-agent chat — not a stack you assemble. | [Who We Are](/about/who-we-are) |
| **Backend architecture platform** | Preferred category name; avoid calling the product merely “BaaS.” | [Who We Are](/about/who-we-are) |
| **Behavior-first** | You model behaviors (API, workflow, actor, worker, …) as units and SDK primitives; engines stay under the platform. | [Who We Are](/about/who-we-are) |
| **Control plane** | Dashboard layer: auth, multi-agent chat, releases, billing, trace query. This is what our user's see. | [Who We Are](/about/who-we-are) |
| **Execution plane** | Managed unit runtime: API / workflow / queue / actor workers and trace export. This is internal and users don't see it. | [Who We Are](/about/who-we-are) |
| **Project** | Top-level workspace; owns chats, units, runtimes, variables, releases, and usage. | [Getting Started](/getting-started) |
| **Unit** | Core primitive: a TypeScript/JavaScript capability with a stable four-segment path. | [Units](/platform/units) |
| **Unit type** | Path segment that selects the runtime model: `api`, `workflow`, `queue_worker`, `actor`, or `common`. | [Units](/platform/units) |
| **Unit path** | Canonical identity: `{context}.{module}.{unit_type}.{unit_name}` (e.g. `billing.payments.workflow.charge`). | [Units](/platform/units) |
| **Context** | First path segment of unit's path — a bounded domain grouping (e.g. `billing`). | [Units](/platform/units) |
| **Module** | Second path segment under a context (e.g. `payments`). | [Units](/platform/units) |
| **Unit name** | Last path segment (`unit_name_slug`); lowercase letters and hyphens only. | [Units](/platform/units) |
| **depends_on** | Explicit dependency list of other unit paths (from `@units/*` type imports). | [Units](/platform/units) |
| **Project isolation** | Every runtime and SDK call is scoped by project — no cross-project access. | [Runtimes](/platform/runtimes) |
| **Managed engines** | Platform-owned Redis, NATS, Postgres, and similar — never exposed as raw vendor APIs. | [Who We Are](/about/who-we-are) |
| **QuickJS** | Embedded JavaScript engine that executes unit code on the execution plane. | [Runtimes](/platform/runtimes) |

## Unit types

| Term | Meaning | Learn more |
| --- | --- | --- |
| **API unit** (`api`) | HTTP request–response unit; entry `handleRequest(req, res)`; auto-documented on deploy. | [API Unit](/platform/units/api-unit) |
| **Workflow unit** (`workflow`) | Durable multi-step orchestration that survives crashes, restarts, and redeploys. | [Workflow Unit](/platform/units/workflow-unit) |
| **Queue Worker unit** (`queue_worker`) | Background job processor with retry, DLQ, batch, concurrency, and rate limits. | [Queue Worker Unit](/platform/units/queue-worker-unit) |
| **Actor unit** (`actor`) | Per-entity durable state with a sequential mailbox (one writer per `actor_id`). | [Actor Unit](/platform/units/actor-unit) |
| **Common unit** (`common`) | Shared library unit; value-importable by other units; no public trigger URL. | [Common Unit](/platform/units/common-unit) |

<Callout type="warning">
  In the **unit path**, the type is always underscored (e.g. `queue_worker`). Hyphenated
  `queue-worker` never appears in the unit path.
</Callout>

## Releases & deploy

| Term | Meaning | Learn more |
| --- | --- | --- |
| **Release** | Deployable snapshot of validated unit changes, tied to a chat session. | [Releases](/platform/releases) |
| **Revision** | Platform versioning term (not “version”): integer for units, dotted number for releases (e.g. `15.4`). | [Releases](/platform/releases) |
| **Unit revision** | Integer version of a logical unit path within a chat. | [Releases](/platform/releases) |
| **Release revision** | Release-level revision derived from the production baseline + chat changes. | [Releases](/platform/releases) |
| **Staging release** | Release marked for staging; deploy to a staging runtime first. | [Releases](/platform/releases) |
| **Production release** | Non-staging release promoted to production after staging proof. | [Releases](/platform/releases) |
| **Base production release** | Production baseline a chat session started from. | [Releases](/platform/releases) |
| **Stale base release** | Live production moved to a release not from this chat — warn, still allow work. | [Avoiding Conflicts](/platform/releases/avoiding-conflicts) |
| **Draft unit** | Unit change not yet published to live. | [Releases](/platform/releases) |
| **Published unit** | Unit released to production runtime. | [Releases](/platform/releases) |
| **Rejected unit** | AI-introduced change discarded by the user. | [Releases](/platform/releases) |
| **Release controller** | Chat UI to review changes and deploy a revision to staging or production. | [Releases](/platform/releases) |
| **Reject controller** | Chat UI to reject unit changes from a step. | [Releases](/platform/releases) |
| **Rollback** | Promote any historical revision back to production. | [Release History](/platform/releases/release-history) |
| **Effective unit set** | Baseline production units overlaid with in-chat session created / modified / removed units in that chat session. | [Releases](/platform/releases) |
| **Technical reviewer** | Automatic validation gate: compiler → lint → rules before a unit row is saved by the AI. | [AI Role](/platform/ai-role) |
