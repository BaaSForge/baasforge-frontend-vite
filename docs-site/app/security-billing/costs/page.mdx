# Costs & Billing

BaaSForge is **pay-as-you-go**: you are charged only for metered usage (compute, storage, and LLM tokens). There is no separate subscription, per-project, or per-unit fee today.

Costs accumulate in real time and are visible in the dashboard during the billing period.

<Callout type="warning">
  **Prices may change over time.** When rates or discounts change, we will notify
  you in advance. This page reflects the current configuration.
</Callout>

## What you pay for

| Cost | Metered by | How it is calculated |
| --- | --- | --- |
| **Compute** | GB·ms of function execution (1 ms minimum) | `usage (GB·ms) × compute rate × subscription discount` |
| **Active storage** (hot) | GB·ms of RAM / actively used memory | `usage (GB·ms) × active storage rate × subscription discount` |
| **Disk storage** | GB·ms of retained block disk | `usage (GB·ms) × disk storage rate × subscription discount` |
| **LLM tokens** | Input + output tokens per model call | `tokens × provider list rate × (1 + platform margin) × subscription discount` |

<Callout type="info">
  Platform fees (subscription, per-project, per-unit, per-stage-runtime) are
  currently **$0** and are not charged. Usage rates above still apply.
</Callout>

### Compute

Every unit invocation is metered by memory × duration in **GB·milliseconds**.

```
cost = memory_GB × duration_ms × compute_rate × subscription_discount
```

### Storage

Storage is split into two tiers today:

- **Active (hot)** — memory / data kept warm for fast access
- **Disk** — block disk capacity retained when data is not in active memory

```
hot_cost  = size_GB × time_ms × active_storage_rate × subscription_discount
disk_cost = size_GB × time_ms × disk_storage_rate   × subscription_discount
```

<Callout type="info">
  **Disk storage is block/disk, not object storage** (it is closer to local or
  attached volume pricing than S3-style buckets). Object storage will be added
  as a **separate metered cost** soon.
</Callout>

### LLM tokens

LLM usage is billed on **input** and **output** tokens separately. We apply a **platform margin** on top of each provider’s published input/output list price, then apply your tier’s subscription discount.

We currently run **Gemini 3.1 Flash Lite Preview** for platform AI. Provider list rates are mirrored in our billing config; see Google’s [Gemini API pricing](https://ai.google.dev/gemini-api/docs/pricing) if those change.

<Callout>
  Your bill always uses the configured provider list rates, plus our margin,
  plus your subscription discount. Other models follow the same formula.
</Callout>

## Discounts

<Callout type="info">
  **Prefer packages over top-ups.** Packages (subscriptions) include discounts
  on compute, storage, and AI token usage (input and output), so they usually
  cost less than topping up. Use a top-up when your package credit runs out and
  you only need more balance until the next billing period (monthly or annual).
  Higher tiers unlock larger discounts and lower usage costs. See the Packages
  page in the dashboard to choose a plan.
</Callout>

<Callout type="important">
  **Credit stays; discounts need an active package.** Package credit remains in
  your balance after the package period ends. Usage discounts apply only while
  you have a non-expired package.
</Callout>

Two discounts can lower what you pay:

### 1. Annual billing discount (20% off)

Applies when you choose **yearly billing** for a paid subscription plan (the plan you pick on the Packages page).

| Billing choice | What you pay |
| --- | --- |
| **Monthly** | The plan’s listed monthly fee, charged each month |
| **Annual** | `monthly fee × 12 × 0.80` — **20% off** the full-year total, paid once for 12 months |

This discount applies **only to that subscription plan fee** — not to metered compute, storage, or LLM usage.

<Callout type="info">
  Example: a plan listed at **$10 / month** costs **$10** billed monthly, or
  **$96 / year** billed annually (`10 × 12 × 0.80`) instead of $120.
</Callout>

### 2. Subscription discount (by tier)

Your package tier lowers the **usage rates** for compute, storage, and LLM. Higher tiers = larger discount (you pay a smaller fraction of the base rate):

| Tier | Subscription discount | You pay |
| --- | --- | --- |
| Tier 1 | `1.00` | Full base rate (no discount) |
| Tier 2 | `1.00` | Full base rate (no discount) |
| Tier 3 | `0.85` | **15% off** usage rates |
| Tier 4 | `0.70` | **30% off** usage rates |

```
your_rate = base_rate × subscription_discount
```

### Monthly cost examples (Tier 1)

These help translate the rates into everyday usage. Scale by your subscription discount for higher tiers (`× 0.85` on Tier 3, `× 0.70` on Tier 4).

Memory uses **1024 MB = 1 GB** (same convention as typical serverless billing).

| Scenario | Exact cost |
| --- | --- |
| **1 GB** of compute running continuously (730 h) | **$21.024** |
| **10 GB·hours** of compute in a month | **$0.288** |
| **100 GB·hours** of compute in a month | **$2.88** |
| 128 MB function × **1M** calls × 100 ms each | **$0.10** |
| **512 MB** (= 0.5 GB) hot storage always on (730 h) | **$1.971** |
| **1 GB** hot storage always on (730 h) | **$3.942** |
| **5 GB** hot storage always on (730 h) | **$19.71** |
| **1 GB** disk always on (730 h) | **$0.0657** |
| **10 GB** disk always on (730 h) | **$0.657** |

```
128 MB × 1M calls × 100 ms:
  memory_GB = 128 / 1024 = 0.125
  GB·ms     = 0.125 × 1_000_000 × 100 = 12_500_000
  cost      = 12_500_000 × $8×10⁻⁹ = $0.10
```

<Callout>
  “1 GB of compute running continuously” means 1 GB of memory allocated for
  every millisecond of the month — useful as an upper-bound reference, not a
  typical workload. Most apps use far less wall-clock compute time.
</Callout>

### LLM variables

| Variable | Meaning |
| --- | --- |
| Provider list price | Published $/1M input and $/1M output tokens from the model vendor |
| Platform margin | Markup on top of that list price (`rate × (1 + margin)`) — currently **margin = 0.25**, so you pay **1.25×** the provider list rate before subscription discount |
| Subscription discount | Same tier table as compute/storage |
| Current model | **Gemini 3.1 Flash Lite Preview** — list **$0.25 / 1M input**, **$1.50 / 1M output** ([Gemini pricing](https://ai.google.dev/gemini-api/docs/pricing)) |

```
customer_token_rate =
  (provider_$per_million / 1_000_000)
  × (1 + platform_margin)
  × subscription_discount
```

**Gemini 3.1 Flash Lite Preview — what you pay (before tier discount):**

| Direction | Provider list | × (1 + 0.25) customer rate |
| --- | --- | --- |
| Input | $0.25 / 1M | **$0.3125 / 1M** |
| Output | $1.50 / 1M | **$1.875 / 1M** |

| Example (Tier 1) | Cost |
| --- | --- |
| **1M** input tokens | **$0.3125** |
| **100k** output tokens | **$0.1875** |
| **1M** input + **100k** output | **$0.50** |

Tier 3 multiplies those by `0.85`; Tier 4 by `0.70`.

## Package limits

Each package tier also caps how many **projects** and **stage runtimes** you can use:

| Tier | Projects | Stage runtimes |
| --- | --- | --- |
| Tier 1 | **2** | **1** |
| Tier 2 | **3** | **1** |
| Tier 3 | **10** | **2** |
| Tier 4 | **40** | **5** |

<Callout type="info">
  Production remains one runtime per project. Stage-runtime limits above are
  the package caps for additional stage environments.
</Callout>

## Summary

1. You pay for **compute**, **hot storage**, **disk storage**, and **LLM tokens**.
2. Higher tiers get a **subscription discount** on those usage rates (up to 30% off on Tier 4).
3. Choosing **annual billing** takes **20% off the subscription plan fee** for the year (not usage).
4. LLM bills follow provider list prices + our margin (**1.25×** today); we currently use Gemini 3.1 Flash Lite Preview.
5. Disk is **block storage**, not object storage — object storage will be a separate meter soon.

<Callout type="warning">
  Rates, margins, discounts, and package limits can change. When they do, we
  will inform you so you can plan ahead. Always treat the dashboard usage view
  as the source of truth for your current period.
</Callout>
